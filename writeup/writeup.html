Core idea: every student × badge has exactly one journey with one state. Every screen — student home, interviewer agenda, ops tracker — is a view of that state, and every change is a validated transition written to an audit log. That's what keeps 15,000 students, a handful of interviewers and a hard Dec 2026 badge deadline consistent.

2 Edge cases & assumptions

Edge cases handled (all demoable in the app)

  • Two students, one slot: row lock on the slot + partial unique index on slot_id; the loser gets “That time was just taken” and a refreshed list.
  • Interviewer over-booked: per-interviewer daily cap; capacity shown to ops respects it.
  • Interviewer can't make it / takes leave: booking is first moved to a free colleague at the same time; only if none, cancelled with priority rebooking (2h lead instead of 12h), no attempt used.
  • Availability edits: booked slots locked, past read-only; weekly pattern rolls forward, one-off removals stick.
  • Late changes: reschedule (max 2) / cancel close 4h before.
  • Call drops / no-show: “Technical issue” uses no attempt; no-show only markable 10 min after start, the 2nd one uses an attempt.
  • Outcome forgotten: auto “Awaiting outcome” at slot end, 24h SLA, overdue surfaced to ops.
  • Unhelpful feedback: rubric + ≥40-char student-facing feedback required for non-pass; interviewer sees a live preview of the exact message. Internal notes are separate.
  • Retake bias: next attempt goes to a different interviewer when one is free; interviewer sees previous attempts' feedback.
  • Malpractice after the badge: flag → On hold (booking released, badge frozen) → confirm nullifies badge, reverses Miles, re-ranks leaderboard. Dismiss restores.
  • Deadline: slots never offered past 31 Dec; a cooldown ending after it is flagged “after deadline” for an ops decision.
  • Eligible but silent: students unbooked 3+ days highlighted; bulk “Nudge”.
  • Wrong person acting: only the assigned interviewer can record; every change is audit-logged with actor and reason.

Assumptions

  • 30-min online interview, all times IST; one student per slot.
  • Students choose a time, not an interviewer — the system assigns the least-loaded qualified interviewer (fairness + load balance).
  • Interviewers are qualified per track; daily cap per interviewer.
  • Eligibility is derived from skill clearances owned by the contest system — this feature never edits them.
  • Max 3 attempts per badge per season; cooldowns 7d (retake) / 21d (fail) / 3d (no-show). All in one config file.
  • Book ≥12h ahead (interviewer prep), up to 14 days out.
  • Nullification is terminal for the season; appeals happen offline with the campus team.

Questions I'd confirm with the GRIT team

  • Fail vs Retake: is the only difference cooldown length, or must a failed student re-clear a skill contest?
  • Attempts: is 3 right? Does a no-show ever count?
  • Deadline: if a cooldown crosses 31 Dec, do we extend, shorten the cooldown, or let it lapse?
  • Nullification: can the student re-attempt that badge later in the season? Do downstream badges also fall?
  • Interviewer identity: show the name before the interview? Avoid same-campus mentors?
  • Interview room: Meet link vs in-app; record for integrity review?
  • Rubric: who owns it, and how do we calibrate pass rates across interviewers?

  • Booking is one transaction: lock the slot row (FOR UPDATE SKIP LOCKED), insert interview, update journey with a version check, write event + notification. Jobs (every minute): slot ended → Awaiting · cooldown ended → Eligible · roll availability forward · SLA reminders.

Built in Django (server-rendered templates, no JavaScript): real logins per role, SQLite/Postgres, DB-level double-booking protection, audit log, 30 automated tests. Exact student messages are in the app and the README.
